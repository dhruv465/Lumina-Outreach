Twilio Media Streams provide access to the raw audio stream of Programmable Voice calls via WebSockets, enabling real-time transcriptions, sentiment analysis, and voice authentication[1].

There are two types of Media Streams:
*   **Unidirectional Media Streams**: Your WebSocket application receives a Call's audio stream but cannot send an audio stream back to Twilio. You can receive inbound, outbound, or both audio tracks. These can be started using `<Start><Stream>` TwiML instructions or via the REST API using the Stream resource.[1]
*   **Bidirectional Media Streams**: Your WebSocket application both receives audio from Twilio and can send audio to Twilio, which is then played on the Call. An example use case is a real-time voice conversation with an AI assistant. These are started using `<Connect><Stream>` TwiML instructions.[1]

Key points and limits:
*   Media Streams can be used in the Ireland (IE1) and Australia (AU1) Regions, with US1 remaining the default.[1]
*   For unidirectional streams, you can stream up to four tracks at a time per Call.[1]
*   For bidirectional streams, only one stream is allowed per Call.[1]
*   Each Media Stream is associated with one WebSocket connection.[1]
*   Your application must allow secure WebSocket connections (TCP port 443) from Twilio and validate the `X-Twilio-Signature` header for security.[1]
